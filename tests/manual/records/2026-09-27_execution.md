# 실행 도구(주문) 시나리오 테스트 (2026-09-27)

README 6.2 실행 도구(주문 확인 → confirm → 실행)가 실제 Jev·LLM에서 설계대로 동작하는지 확인한 수동 테스트 기록이다. id의 `-1`·`-2`는 앞 시나리오에 이어지는 대화라는 뜻이며, `--only`로 돌릴 때 앞 시나리오를 함께 넣는다. `python -m tests.manual.smoke_flow --set execution`, 시나리오는 `scenarios/execution.json`.

## 구성

| 항목 | 값 |
|---|---|
| Harness | main `f86bd43` + 이 기록의 수정 |
| Jev | OpenRouter Decisions API, `~typesafe/jev-latest` |
| 답변·인자 LLM | OpenRouter `openai/gpt-6-luna` |
| Broker | **가짜** (`smoke_flow.py`의 고정 응답). 삼성전자 285,500 / 삼성전자우 231,000 / SK하이닉스 351,000원. 주문은 삼성전자우만 `UNKNOWN`, 나머지는 `ACCEPTED`. 실제 주문·KIS 호출 없음 |
| Search | NAVER API HUB 실제 키 (o6-2에서 사용) |
| 저장소 | `InMemoryConversationStore`, 한 대화에서 순서대로 진행 |

## 1차 실행에서 드러난 문제와 수정

1차 실행(같은 시나리오)은 12개 중 5개가 120초 읽기 라우팅 제한까지 반복하다 `GENERATION_FAILED`로 끝났고, 실패한 Turn이 저장되지 않아 뒤 시나리오(o1-1·o3-1·o6-1·o9-1·o9-3)도 이어서 해석되지 못했다.

1. **준비 뒤에도 Jev가 같은 도구를 계속 선택**
   - "삼성전자 5주 팔아줘"는 확인 대기까지 정상으로 만들어졌다. 그런데 Jev는 answer 대신 order를 다시 골라(85~90%) 120초 동안 약 30번 반복했다. 인자 부족(o6)·모호(o9)도 되묻지 않고 order만 반복했다.
   - 원인: order 설명이 "매수·매도를 요청하면 선택"이라, 요청이 남아 있는 한 계속 해당된다고 판단했다.
   - 수정: 실행 도구를 준비한 뒤에는 Jev를 다시 부르지 않고 바로 답변한다. 준비 결과는 늘 확인 문장이나 되묻기라 다음 행동이 답변뿐이다. 못 찾은 종목을 자동으로 다시 시도하던 흐름은 없애고 공식 종목명을 되묻는다.
2. **"삼전"을 종목명으로 바꾸지 못함**
   - 인자 LLM이 `name`을 null로 냈다. "사용자가 말하지 않은 것은 null, 추측 금지" 문구가 별명 변환까지 막은 것으로 보인다.
   - 수정: 인자 설명을 "별명·약칭은 공식 종목명으로 바꿈(삼전 → 삼성전자, 하닉 → SK하이닉스), 대화 전체에서 채움, 매수/매도·수량·가격은 지어내지 않음"으로 바꿨다.

반복 자체를 막는 범용 상한(도구별 최대 횟수 등)은 검토했지만 넣지 않았다. 실제 원인은 1번 구조였고, 읽기 도구에서는 반복이 관찰되지 않았기 때문이다. 다시 보이면 "같은 도구는 한 Turn 최대 5번, 도달 시 선택지에서 뺌"을 넣는다.

## 관찰 사항

- **o9 "삼성 10주 사줘"**: 별명 변환 지침 때문에 LLM이 "삼성"을 삼성전자로 확정해 Broker 모호 후보(`AMBIGUOUS`)까지 가지 않았다. 확인 문장에 정확한 종목명·코드가 나오므로 사용자가 바로잡을 수 있고, 모호 후보 처리는 단위 테스트가 다룬다. 실제 사용에서 문제가 되면 "여러 종목이 떠오르면 변환하지 말 것"을 추가한다.
- 확인 문장의 시각(`00:31 기준`)은 테스트 시각(한국 시각 자정 무렵)이다.
- o3-2 "하지 말자" 뒤 확인 대기는 그 Turn이 끝나며 버려졌다(주문 0건 유지).

관찰:

- **o13-2 답변 문구**: 확인 대기가 버려진 뒤 "응"에 "여기서는 실제 주문을 접수할 수 없어서… 증권사 앱에서 주문해 주세요"라고 답했다. 동작(주문 없음)은 맞지만 PIA가 주문을 못 한다고 오해하게 하는 문구다. 테스트용 시스템 프롬프트("Do not give personalized buy/sell advice")에 주문 기능 설명이 없어서 생긴 것으로 보인다. PIA 연결 때 실제 시스템 프롬프트에 "주문은 확인 문장 바로 다음 메시지로 동의할 때만 실행되며, 지났으면 다시 요청하도록 안내"를 넣는다.
- **o19**: 한 번에 한 주문만 준비하는 동작과 나머지 주문을 답변에서 밝히는 것 모두 설계대로다. 두 주문 동시 처리는 넣지 않는다.
