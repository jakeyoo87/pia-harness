# 공시 재무 조회 도구: reported_financials

- 작성일: 2026-10-16 (Asia/Seoul)
- 저장소·브랜치: pia-harness `codex/reported-financials`
- 기준: main `088fd6e` (v0.7.11)
- 담당: Codex 계획 작성, Claude 계획 검토. 구현·구현 검토 담당은 계획 확정 뒤 지정한다.
- 현재 단계: 계획만 작성. 구현·릴리스·PIA 연동·AWS 변경·배포는 이번 작업에 포함하지 않는다.

## 1. 배경과 대화에서 합의한 방향

사용자가 기업의 실제 재무제표와 과거 실적을 물으면, 웹에서 숫자를 찾는 대신 공식 공시 API에서 확인하게 한다. 미래 전망치와 혼동하지 않도록 이름은 `financials` 대신 **`reported_financials`(공시 재무 조회)**로 한다. 나중의 전망치 도구와 이름·설명을 구분한다.

- 국내는 OpenDART, 미국은 SEC EDGAR를 사용한다. 무료 공시 자료가 대상이며 Alpha Vantage를 전제로 하지 않는다.
- 읽기 도구 하나로 손익계산서·재무상태표·현금흐름표의 공시된 숫자와 과거 추이를 조회한다.
- 회사가 공시한 실제 값, 보고 기간, 공시일, 통화, 연결/별도 구분, 원문 출처를 함께 전달한다.
- 사용자 추가 결정(2026-10-16): 4분기 손익 금액 5개에 한해 **연간 − 3분기 누적**을 계산하고 계산값임을 표시한다. EPS·재무상태·현금흐름에는 이 계산을 적용하지 않는다. 구체 조건은 §5에 적는다.
- 예상 실적·컨센서스·가이던스·목표주가·투자의견·시세·과거 PER/PBR은 이 도구의 제공 범위가 아니다.
- 도구가 지원하지 않는 정보와, 지원하지만 조회되지 않은 정보를 LLM이 구분해야 한다. 누락은 0이 아니다.

아래 인자, 기업 식별, 대표 계정, 기간 선택은 **Codex 설계 제안이며 Claude 검토 대상**이다. 사용자 결정으로 이미 확정된 세부 사양은 아니다.

## 2. 구조와 변경 범위

기존 `NaverNewsSearch`처럼 host가 생성해 등록하는 `ReadToolDefinition`을 사용한다.

```text
PIA: OpenDART 키·SEC 식별용 User-Agent 설정 주입, 도구 등록
  → Harness reported_financials
      → country=kr: OpenDART 회사 식별 → 공시 재무정보
      → country=us: SEC 회사 식별 → Company Facts(사실값과 공시 메타데이터)
  → ReadToolResult(기간·단위·수치·출처)
  → 기존 모델 루프가 설명·표·차트 작성
```

- 계좌 연결과 무관한 공개 기업 자료다. KIS Credential·Token·회원 계좌를 사용하지 않는다.
- Harness가 API를 직접 호출한다. Broker의 네 액션·내부 경로·IAM을 확장하지 않는다.
- 기존 읽기 도구 예산·동시 실행·취소·Turn 저장·출처 번호 처리를 그대로 사용한다. Orchestrator나 확인 흐름을 바꾸지 않는다.
- `reported_financials.py`에 도구·설명·공통 결과를, `dart_financials.py`와 `sec_financials.py`에 제공기관별 식별·요청·해석을 둔다. 별도 공급자 플러그인 계층을 만들지 않는다.
- 기존 `httpx`와 표준 라이브러리로 구현한다. `.tool()`, `.aclose()`, 주입 가능한 HTTP client는 기존 읽기 도구 방식과 맞춘다.
- 기업 식별 목록만 제공기관별 프로세스 메모리에 보관한다. 영속 DB·정기 수집기·재무 데이터 캐시 서버는 1차에 두지 않는다.
- PIA의 키 저장·읽기 권한·등록·프롬프트·핀 변경은 후속 연동 작업에서 계획한다. 이 문서가 그 AWS 변경이나 배포 승인을 뜻하지 않는다.

## 3. 도구 인자 제안

| 인자 | 의미 | 기본값 |
|---|---|---|
| `name` | 국내 종목코드 또는 공식 회사명. 미국은 티커 또는 공식 영문 회사명 | 필수 |
| `country` | `kr`, `us` | 필수 |
| `frequency` | `annual`, `quarterly` | `annual` |
| `end_year` | 값의 기간 종료일이 이 달력연도 말까지인 자료. 생략하면 공개된 최근 보고 기간부터 선택 | 생략 |
| `count` | 세 재무제표를 함께 반환할 보고 기간 수. 실제 확보한 개수를 함께 표시 | annual 기본 5·상한 10, quarterly 기본 4·상한 8 |

예: `{"name":"005930","country":"kr","frequency":"annual","count":5}`. 미국 예: `{"name":"NVDA","country":"us","frequency":"quarterly","count":4}`. 한 번에 손익·재무상태·현금흐름 대표 계정을 함께 반환하므로, 같은 회사의 매출과 부채를 보려고 두 번 부르지 않는다.

- `end_year`는 당시 알려진 자료만 재현하는 시점 조회가 아니다. 값의 실제 기간 종료일을 기준으로 자르고, 그 기간의 수치는 조회 시점에 공개된 최신 정기공시에서 읽는다. SEC의 `fy`·`fp`를 이 상한이나 값의 기간 판정에 사용하지 않는다. 최초 초안의 회계연도 상한 표현은 이 종료일 기준 제안으로 바꾼다. 국내 연도·기간 대응은 OpenDART 표본 확인 뒤 맞춘다.
- `count`는 재무제표 개수나 개별 계정 수가 아니다. 연간 10·분기 8을 넘는 요청은 한도를 알리고, 잘못된 요청을 조용히 잘라 성공으로 표시하지 않는다. 기본값은 생략한 경우에만 적용한다.
- 국내는 OpenDART 고유번호 목록에서 종목코드·회사명을, 미국은 SEC 공식 티커 목록에서 티커·영문명을 찾아 내부 식별자로 바꾼다. 내부 corp_code·CIK를 모델이 만들어 보내지 않는다.
- 이름은 정확 일치만 우선 지원한다. 여러 회사면 후보로 되묻고, 찾지 못하면 공식 이름·코드 확인을 안내한다. 별도 별칭 사전·유사도 검색을 만들지 않는다.
- 스키마에는 지원하는 frequency와 count 범위만 연다. 인자 오류는 요청을 보내지 않고 결과 문장으로 알린다. 잘못된 값을 기본값으로 바꾸지 않는다.

## 4. 1차 제공 항목과 제공하지 않는 항목

| 재무제표 | 대표 계정(공시값, 아래 Q4 손익 계산만 예외) |
|---|---|
| income | 매출, 매출원가, 매출총이익, 영업이익, 순이익, 기본 EPS, 희석 EPS |
| balance | 총자산, 총부채, 자본총계, 현금및현금성자산, 공시된 단기·장기 차입금 항목 |
| cashflow | 영업·투자·재무활동 현금흐름, 공시된 유형자산 취득 지출 |

- 제공기관별 표준 계정 ID를 작은 대응표로 정한다. 개념마다 의미가 같은 후보 태그 몇 개를 두고 **기간마다** 선택한다. 회사 전체에 태그 하나를 고정하지 않는다. 선택한 계정 ID·명칭을 결과에 남긴다. 국내 ID는 OpenDART 표본 확인 뒤 맞춘다.
- SEC에서 후보 태그에 같은 기간의 값이 여러 개 있으면 먼저 아래 최신 정기공시 규칙을 적용한다. 같은 공시·기간·단위에 복수 후보가 있으면 대응표의 순서로 고른다. 오래된 우선 태그 때문에 더 최근의 다른 후보 태그 값을 놓치지 않는다.
- 회사 전용 계정·세부 항목이 대응되지 않으면 조회되지 않은 항목으로 표시한다. 이름이 비슷하다는 이유로 LLM이 다른 계정을 대신 고르지 않는다. 은행 등 업종별 전체 계정 사전은 1차 범위가 아니다.
- 재무제표 모든 계정을 한꺼번에 반환하는 도구가 아니라, 위 대표 계정 조회다. 도구 설명에도 이 범위를 적는다.
- 단기·장기 차입금이나 현금성자산의 세부 항목을 임의로 합쳐 총차입금·순현금을 만들지 않는다.
- 파생값 계산은 §5의 Q4 손익 금액만 허용한다. 잉여현금흐름·증가율·이익률·ROE·PER/PBR은 계산하지 않는다. EPS도 순이익과 주식 수로 재계산하거나 연간 EPS에서 누적 EPS를 빼지 않고, 공시된 값만 쓴다.
- 배당·자사주·주주·임원 정보는 OpenDART에 별도 기능이 있지만 **이 도구의 1차 범위 밖**이다. 해당 서비스 자체에 없다고 설명하지 않는다.
- 회사 가이던스·제품/사업부별 매출·상세 주석은 공시 원문에 있을 수 있다. 이 도구는 해당 원문을 분석하는 기능까지 포함하지 않는다.

## 5. 제공기관과 기간 선택

### 공통 선택 규칙: 각 기간을 담은 가장 최근 정기공시

**같은 회사·계정 개념·기간·연결/별도 기준·단위의 값은, 그 기간을 담은 가장 최근 정기공시에서 읽는다.** 정정과 중복을 별개 상태나 예외 목록으로 다루지 않는다. 공시일이 다른 계정을 한 행에 표시해도 각 값의 출처를 남기며, 전체가 한 보고서에서 왔다고 표현하지 않는다.

- 최신은 조회 시점에 공개된 정기공시 기준이다. 당시 알려진 자료를 재현하는 백테스트나 전망치가 아니다. 공시일과 조회 시각을 구분한다.
- 모든 결과는 **세 재무제표를 함께** 담는다. `count`는 선택한 보고 기간 수이고, 그 안의 BS 기말·IS 단독 분기·CF 누적은 각각 기준을 표시한다.
- BS는 기말 잔액, IS·CF는 기간 값이다. 값은 Decimal 또는 원문 숫자 문자열로 보존하고, 통화·주당 금액·누락을 구별한다. 서로 다른 통화·연결 기준·기간 길이는 같은 비교값으로 숨기지 않는다.

### 국내: OpenDART — Local Codex 표본 확인 대기

- 회사 식별은 `corpCode.xml`의 공식 종목코드·고유번호·회사명을 사용한다.
- 재무정보는 `fnlttSinglAcntAll.json`을 사용한다. 한 응답의 BS·IS(CIS)·CF를 모두 읽는다. 공시 검색·기업개황을 메타데이터 확인만을 위해 추가 호출하지 않는다.
- 사업보고서의 당기·전기·전전기(`thstrm`·`frmtrm`·`bfefrmtrm`) 비교 열을 재사용한다. 같은 기간이 다시 나오면 더 최근 보고서의 비교 열을 선택한다. 예를 들어 최신 보고서에서 3개 연도를 확보하고 다음 필요한 보고서에서 나머지 2개를 확보하면 **연간 5개 기간은 재무 API 2회**로 채운다. 연도별로 무조건 하나씩 부르지 않는다.
- 응답의 `rcept_no`에서 접수일(앞 8자리)과 원문 링크를 만든다. 비교 열의 공시일도 값을 가져온 그 보고서의 접수일이다. 값의 과거 기준연도와 혼동하지 않는다.
- 연결(CFS)을 우선한다. 연결 자료 없음이 확인되어 별도(OFS)를 사용하면 기준을 명시하고 최신 값 선택에서도 두 기준을 구분한다. OFS 확인 등 실제 추가 호출이 필요한 경우 호출 수에 포함한다.
- 손익의 `thstrm_amount`(분/반기 3개월 값)와 `thstrm_add_amount`(누적), CF의 공시된 누적 기준을 구별한다. 비교 열의 실제 기간·금액 선택과 CFS/OFS·태그 대응은 **Local Codex 결과가 오면 이 절에 반영**한다. 국내 응답은 아직 확인 완료로 표시하지 않는다.
- 위 2회는 필요한 비교 열이 모두 있는 정상 경로의 목표다. 정확한 최신 보고연도 선택, 누락·정정·비교 열의 기간 정보와 국내 호출 예산은 표본 확인 뒤 확정한다. 이를 미리 해결하려고 추가 공시 검색이나 누락 복구 장치를 넣지 않는다.

### 미국: SEC EDGAR — Claude가 확인한 응답 반영

- 공식 티커 목록에서 CIK를 확인하고 `data.sec.gov/api/xbrl/companyfacts/CIK##########.json`을 **한 번** 읽는다. 사실값 자체의 `accn`·`filed`·`form`·`start`·`end`·단위를 사용하며 `submissions`를 추가 호출하지 않는다.
- 허용 공시 종류는 **`10-K`, `10-Q`, `10-K/A`, `10-Q/A`**뿐이다. 먼저 이 범위로 거른 뒤 같은 기간 값에서 `filed`가 가장 늦은 것을 고른다. `DEF 14A`의 임원 보수표 등에 나온 값이 재무제표의 최신값을 덮지 않게 한다. 20-F·6-K 등 다른 양식은 1차 범위 밖이며, 미국 거래소에 상장됐다는 이유만으로 모든 외국 기업을 지원한다고 설명하지 않는다.
- Company Facts의 표준 태그·회사 전체 사실값이 대상이다. 회사 전용 태그·부문별 차원 데이터를 모두 포함하는 API로 취급하지 않는다.
- 기간 식별은 기간 계정의 **`start`·`end`**, 기말 계정의 **`end`**로 한다. 실제 기간 길이로 단독 분기·누적·연간을 구별한다. 52/53주 회계연도를 달력 분기나 고정 90일로 잘라 바꾸지 않는다.
- **`fy`·`fp`는 그 값을 실은 보고서의 표기**다. 다음 해 공시에 실린 비교 열에도 다음 해 fy/fp가 붙으므로 값의 회계연도·분기로 사용하지 않는다. 응답에서 확인할 수 없는 회계연도 라벨은 만들지 않고 실제 기간 날짜로 표시한다.
- NVDA 표본에서 매출 태그가 과거 `RevenueFromContractWithCustomerExcludingAssessedTax`, 최근 `Revenues`로 바뀐 것을 확인했다. §4의 후보 태그를 기간별로 선택해 과거 계정을 놓치지 않는다.
- 이용자 식별용 User-Agent는 host 설정으로 주입하고 SEC 접근 지침을 따른다. 이번 반영 작업에서는 SEC를 다시 호출하지 않는다.

### Q4 손익 계산 — 사용자 결정

- 최근 SEC 표본에는 Q4 단독값이 없었고 일부 과거 연도에는 있었다. **원문에 해당 Q4 단독 공시값이 있으면 그 값을 사용**하고, 없을 때에만 아래 계산을 적용한다.
- 대상은 **매출·매출원가·매출총이익·영업이익·순이익** 다섯 금액이다. Q4 = 연간 − 3분기 누적으로 계산한다. EPS·재무상태·현금흐름에는 이 차감을 적용하지 않는다. 실제 공시된 EPS·기말 잔액·연간/누적 CF가 있으면 그 기준을 그대로 표시하며 Q4 단독값으로 바꾸지 않는다.
- 두 입력은 각각 최신 정기공시 규칙으로 선택한 공시값이어야 한다. 같은 회사·같은 계정 개념·같은 회계연도 시작·같은 연결/별도 기준·같은 통화여야 하며, 연간 기간 안에 3분기 누적 기간이 들어가야 한다. 다른 연도·통화·기준의 값을 빼지 않는다. 원문 태그가 달라도 §4의 같은 개념으로 확인된 후보이면 두 원래 태그를 남긴다.
- 결과에는 **`계산값(연간 − 3분기 누적)`**, 연간값과 누적값, 각 기간·공시일·보고서 원문 출처를 남긴다. 계산값을 공시 원문에 그대로 있는 값으로 인용하지 않는다. Q4 기간은 3분기 누적 종료 다음 날부터 연간 종료일까지다.
- 입력이 없거나 기준을 맞출 수 없으면 그 항목의 Q4 계산값은 미제공으로 표시한다. 회사에 Q4 실적이 없거나 0이라고 단정하지 않는다. 연간을 네 등분하거나 반기−1분기 차감 등 다른 계산으로 확대하지 않는다.
- Q4를 count에 포함하더라도 근거 수집은 같은 Company Facts나 필요한 국내 보고서 응답에서 한다. SEC의 별도 보고서 다운로드·submissions 호출을 추가하지 않는다. 국내 입력 필드·기간 확인은 Local Codex 표본 확인 뒤 확정한다.

## 6. LLM 안내와 결과 계약

실제 영문 도구 설명은 다음 한국어 계약과 같은 뜻으로 작성하고, 시나리오에서도 그 설명을 그대로 사용한다.

> 국내·미국 기업의 과거 공시 재무정보를 조회하고 손익·재무상태·현금흐름 대표 계정을 한 번에 반환한다. 미국은 10-K/10-Q와 그 정정 공시가 대상이다. Q4 손익 금액 중 원문 단독값이 없는 항목은 연간−3분기 누적 계산값을 명시해 제공한다. EPS·재무상태·현금흐름은 이 방식으로 계산하지 않는다. 예상 실적·컨센서스·가이던스·목표주가·투자의견·시세·과거 PER/PBR·배당 전용 조회는 지원하지 않는다. 시세·계좌는 broker, 전망치·가이던스·목표주가는 웹 검색으로 확인한다. 누락은 0이 아니며 과거 실적을 예상치 대신 제시하지 않는다. 각 값의 실제 기간·기준·공시값/계산값 표시와 출처를 유지한다. 계좌 연결은 필요 없다.

결과는 기존 `ReadToolResult` 하나로 반환한다.

- 머리말: 제공기관, 확인된 회사명·식별자, 세 재무제표 함께 조회, frequency, 요청/실제 기간 수, 조회 시각, 최신 정기공시 기준이라는 설명.
- 각 기간의 BS·IS·CF 값: 원래 계정 ID·명칭·금액·단위, 실제 기간·기말과 단독 분기/누적/연간 구분, 연결/별도 기준, 값을 가져온 보고서 종류·접수번호·공시일·원문 출처. 같은 기간 안에서 공시일이 다르면 각 값에 남긴다. SEC fy/fp로 값의 기간을 바꾸지 않는다. 확인하지 못한 날짜·라벨은 만들지 않는다.
- Q4 계산값: 계산 표시와 두 입력값·두 원문 출처를 함께 남긴다. 계산 표시를 Turn이나 후속 차트에서 생략하지 않도록 도구 결과에도 명시한다.
- 원문 출처는 `ToolLink`로도 반환해 기존 번호 출처와 다음 Turn의 읽기에 사용한다. 키가 포함된 OpenDART 요청 URL을 출처로 내보내지 않는다.
- 기간은 오래된 순서로 표시한다. 일부 기간·항목을 못 받으면 확보한 범위와 빠진 범위를 밝힌다. 회사가 해당 자산·이익이 없다고 단정하지 않는다.
- 설명·schema·검사가 같은 지원 목록을 사용한다. 별도 LLM 분류기나 Orchestrator 전용 분기를 추가하지 않는다.

| 결과 상황 | 모델에게 알릴 내용 |
|---|---|
| 미지원 요청·인자 | 이 도구의 범위와 사용할 다른 도구. 전망치를 과거 실적으로 대신하지 말 것 |
| 대상 미확인·여러 후보 | 공식 이름·코드 확인 또는 후보로 되묻기 |
| 지원 항목/기간의 자료 없음 | 해당 범위에서 조회되지 않음. 0이나 회사 전체의 부재를 뜻하지 않음 |
| HTTP/제공기관 오류·한도 | 이번 조회 실패. 오류 응답을 자료 없음으로 바꾸지 않음 |
| 정상/일부 자료 확보 | 확인된 숫자·기준·출처와 미확인 범위 |

HTTP 요청은 고정 공식 주소를 쓰고 기존 도구처럼 환경 프록시·redirect를 사용하지 않는다. 원문 응답·키·키가 들어간 요청 URL은 결과나 로그에 남기지 않는다. 자동 재시도·다른 데이터원으로의 자동 전환은 두지 않으며, 이후 도구 선택은 기존 모델 루프에 맡긴다. 한 요청 전체가 실패한 경우와 특정 기간만 실패한 경우를 결과에 명시한다.

2. **"각 기간의 값은 그 기간을 담은 가장 최근 공시에서 읽는다" 규칙 하나로 정정·중복을 처리한다(국내·미국 공통).** §5의 "보고서 선택 단계에서 정리"를 이 한 문장으로 확정해 달라.

4. **`count` 상한을 낮춘다: 연간 10, 분기 8.** OpenDART는 2015년 이후만 있어 연간 20은 채울 수 없고, 분기 20은 국내에서 보고서 호출 수만 늘린다.

### 사용자 결정이 필요한 것 (Claude가 사용자에게 묻는다)

5. **4분기 단독 값.** 국내·미국 모두 4분기는 따로 공시되지 않는다(사업보고서·10-K는 연간). 지금 계획(계산 금지)대로면 "최근 4개 분기 매출"을 물을 때 매년 4분기가 비고, 1~3분기 + 연간이 나온다. 선택지: (a) 계획대로 비워 두고 "4분기는 단독 공시가 없다"고 안내, (b) 손익 계정에 한해 "연간 − 3분기 누적"을 **계산값 표시와 함께** 넣는다(현금흐름·재무상태는 계산하지 않음). 결정 전까지는 (a)로 둔다.

### 덜어도 되는 것 / 표현 정리

- §3 "미국 한글명은 웹 검색으로 티커 확인" 안내는 빼도 된다. 모델이 주요 미국 기업 티커를 알고, 모르면 기존처럼 스스로 검색한다. 설명에는 "미국은 티커 또는 공식 영문명"만 적는다.
- §2 "기업 식별 목록은 프로세스 메모리"는 그대로 좋다. 첫 조회 때 받는 시간(OpenDART 고유번호 ZIP, SEC 티커 목록)만 구현 때 재고, 별도 갱신 장치는 두지 않는다(새 상장사는 재시작 때 반영 — 실제 문제 아님).
- §4 대표 계정 대응표: 국내는 `account_id`(IFRS 표준 ID) 기준이라 짧다. 미국은 같은 개념이 회사마다 다른 태그(예: 매출 `Revenues` / `RevenueFromContractWithCustomerExcludingAssessedTax`)로 오므로 **개념마다 후보 태그 몇 개를 순서대로** 두는 정도면 된다. 업종별 사전은 계획대로 범위 밖.
- §5 "공시일과 조회 시각 구분", §6 결과 상황 표는 그대로 좋다. 다만 §5·§6의 금지 문장 중 결과 행에 기간·기준·누적 여부가 적혀 있으면 자연히 지켜지는 것(같은 차트에 섞지 않기 등)은 설명에 한 줄로 합쳐 도구 설명 길이를 줄인다.

### 사용자 결정 (2026-10-16)

- **5번 4분기 단독값: (b).** 손익 계정(매출·매출원가·매출총이익·영업이익·순이익)에 한해 4분기 = 연간 − 3분기 누적으로 계산해 넣고, 그 값에 **"계산값(연간 − 3분기 누적)"을 표시**한다. 두 값은 같은 기준(연결/별도·통화)이고 각각 공시된 값일 때만 계산한다. EPS·재무상태·현금흐름은 계산하지 않는다(EPS는 주식 수가 분기마다 달라 빼기로 맞지 않는다). 그 밖의 "파생값 만들지 않음" 원칙은 그대로다.

### SEC 실제 응답 확인 (2026-10-16, 사용자 요청, NVDA Company Facts 1회 공개 조회)

키 없는 공개 API를 한 번 읽었다(`CIK0001045810`, 약 0.3MB gzip). 계획에 반영할 사실:

- **4분기 단독값은 최근 연도에 없다.** 최근 회계연도는 1~3분기 3개월 값과 9개월 누적, 연간(FY)만 있고, 연말로 끝나는 3개월 값이 없다. 2020년 이전 10-K에는 분기 3개월 값이 들어 있던 해도 있어 회사·연도마다 다르다 → 결과에 "4분기 단독 공시 없음"이 실제로 자주 나온다(위 5번 결정이 실제 문제임을 확인).
- **"가장 최근 공시" 규칙은 공시 종류를 10-K·10-Q(정정 /A 포함)로 한정해야 한다.** 순이익(`NetIncomeLoss`)의 연간 값 중 가장 늦게 접수된 것이 위임장 설명서(`DEF 14A`, 임원 보수 표)였다. 종류를 거르지 않으면 재무제표가 아닌 문서의 값을 고른다.
- **`fy`·`fp`는 그 값을 실은 공시의 회계연도·분기이지, 값의 기간이 아니다.** 예: 2024-07-28로 끝나는 3개월 값이 `fy 2026, fp Q2`(다음 해 2분기 보고서의 비교 열)로 붙어 있다. 기간은 `start`·`end`(일수)로 정하고, `fy`·`fp`로 기간을 정하지 않는다.
- **같은 개념의 태그가 해에 따라 바뀐다.** NVDA 매출은 2022 회계연도까지 `RevenueFromContractWithCustomerExcludingAssessedTax`, 그 뒤 `Revenues`. 개념마다 후보 태그를 두고 기간마다 있는 것을 쓰는 방식이 필요하다(덜어도 되는 것의 "후보 태그" 항목과 같음).

OpenDART는 인증키가 필요해 아직 확인하지 않았다(사용자가 키를 발급하면 표본 확인).

### Codex에게 (다음 할 일)

- 위 1~4와 "덜어도 되는 것"을 계획에 반영해 같은 브랜치에 커밋하고, 5는 사용자 결정 전까지 (a)로 적어 둔다. 반영 뒤 재검토는 바뀐 절만 본다.
- 실제 API 호출·키 발급·AWS 변경은 여전히 하지 않는다. OpenDART 키 발급과 보관 위치는 PIA 연동 계획에서 사용자와 정한다.

계획 본문에 반영했다. Claude 검토 원문은 위에 기록으로 보존하며, 마지막의 "사용자 결정 전까지 (a)" 요청은 이후 확정된 사용자 결정 (b)로 대체한다.

기간 기준 정리에 따라 end_year도 SEC의 공시 fy가 아닌 **실제 기간 종료일의 달력연도 상한**으로 제안했다. 날짜로 기간을 식별하면서 확인되지 않은 회계연도 라벨을 붙이지 않기 위한 변경이다. 국내 사업연도·실제 기간의 대응과 정확한 최신 보고기간 선택은 Local Codex 표본 결과를 받은 뒤 이 계획에서 확정한다.

이번 작업은 이 계획서만 수정했다. 실제 API 호출·키 조회/발급·AWS 변경·구현·모델 실행은 하지 않았다.

## Claude 재검토 (2026-10-16, 커밋 a30b79f)

판정: 1차 반영 요청 1~4, SEC 확인 사항, Q4 사용자 결정이 본문(§3~§7)에 일관되게 들어갔다. statement 제거·count 상한·10-K/10-Q(/A) 필터·start/end 기간·기간별 후보 태그·Q4 계산(다섯 손익 금액, 두 입력·두 출처·계산 표시, EPS·BS·CF 제외) 모두 사용자 결정과 맞다. end_year를 실제 기간 종료일의 달력연도로 바꾼 것도 fy/fp를 쓰지 않는 규칙과 맞다. **구현 전에 아래 두 가지를 더 정해 달라.**

1. **모델 시나리오를 구체적인 목록으로 적는다.** §7에 "모델 시나리오" 한 줄만 있어 무엇을 기대하는지 정해지지 않았다. 기존 `tests/manual/smoke_flow.py`와 `scenarios/{분류}.json` 형식(`message`·`expect`·`expect_args`, 기대 없는 항목은 관찰)을 그대로 쓰고, 새 분류 `financials.json`과 가짜 제공기관(고정 응답, 실제 OpenDART·SEC 호출 없음)을 두는 것으로 계획에 적는다. 새 실행기나 판정 장치는 만들지 않는다. 최소 목록(예시 문장은 바꿔도 됨):
   - 국내 연간: "삼성전자 최근 5년 매출이랑 영업이익" → `reported_financials` `{name: 삼성전자 또는 005930, country: kr, frequency: annual}`
   - 미국 분기: "엔비디아 최근 4개 분기 실적" → `{name: NVDA, country: us, frequency: quarterly}`, 답에 Q4 계산값 표시가 남는지 관찰
   - 한 번 호출: "SK하이닉스 부채랑 현금흐름도 같이" → 도구 1회(세 재무제표 동시)
   - 범위 밖 → 다른 도구: "삼성전자 내년 실적 전망" → `web_search`, "엔비디아 지금 주가" → `broker`(quote)
   - 미지원 관찰: "삼성전자 과거 5년 PER 추이", "애플 배당 내역" → 이 도구가 직접 준다고 답하지 않는지 관찰

   - 모든 항목에서 order·confirm 0건
2. **결과 크기: 출처를 값마다 반복하지 않는다.** 지금 계약은 값마다 보고서 종류·접수번호·공시일·출처를 남기라고 읽힌다. 대표 계정 약 18개 × 분기 8개 = 약 140개 값에 각각 출처를 붙이면 결과가 매우 길어진다(같은 기간 값은 대부분 같은 공시에서 온다). **출처는 번호 붙인 목록으로 한 번만 적고, 기간(또는 값)은 그 번호만 가리키게** 한다. 기간 안에서 공시가 다른 값만 그 값 옆에 번호를 따로 단다. Q4 계산값은 두 입력의 번호를 단다. 뜻은 같고 길이만 줄어든다.
