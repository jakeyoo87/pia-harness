# 미국 주식: 종목 조회·계좌·주문

날짜: 2026-10-06 (Asia/Seoul)
브랜치: pia-harness `claude/us-stocks`(계획, harness 구현), pia-broker 같은 이름(Broker 구현), pia 같은 이름(프롬프트·핀)
담당: Claude 계획·구현·실호출 확인, Codex 계획·구현 검토와 병합·릴리스·배포
기준: harness main `773ee02`(v0.7.4), Broker main `2e3f96c`, PIA main `6bf7d1c82`

## 목표

미국 주식을 국내 주식처럼 PIA에서 조회하고 주문한다. 지금은 해외 종목을 웹 검색으로 답하고, 계좌·주문은 국내만 된다.

- "엔비디아 얼마야?", "테슬라 1년 차트", "애플 PER"
- "내 계좌 보여줘"에 미국 보유 종목·달러 예수금까지
- "엔비디아 몇 주 살 수 있어?", "엔비디아 2주 사줘", "테슬라 다 팔아줘"

## 1. 구조: 도구·경로는 그대로, Broker가 시장으로 가른다

| 도구·액션 | 바뀌는 것 |
|---|---|
| `broker` `account` | 결과에 미국 부분(달러 예수금, 미국 보유 종목, KIS 원화 환산 합계) |
| `broker` `account` + `name` | 미국 종목이면 매수 가능(달러)·보유 |
| `broker` `quote` + `name` | 미국 종목이면 해외 시세 |
| `broker` `history` prices + `name` | 미국 종목이면 해외 기간 시세 |
| `broker` `history` investors + `name` | 미국 종목은 없음(KIS가 주지 않음) |
| `broker` `ranking` | 국내만(그대로) |
| `order`·`confirm` | 미국 매수·매도(지정가) |

- Broker 경로는 그대로다: `/instruments`, `/quote`, `/history`, `/account`, `/orders`. **새 경로·IAM 변경 없음.**
- 모델은 국내인지 미국인지 고르지 않는다. 종목 검색 결과의 시장으로 Broker가 어느 KIS API를 부를지 정하고, 응답에 통화가 붙는다.

## 2. 종목 식별과 검색 (Broker)

### 2.1 코드

- 국내는 지금처럼 6자리 코드(`005930`). 미국은 **`거래소:티커`** 한 문자열(`NAS:NVDA`, `NYS:BRK/B`, `AMS:SOXL`). 거래소 코드는 KIS 시세 API·마스터의 `NAS`·`NYS`·`AMS`를 쓴다.
- harness는 코드를 해석하지 않고 검색 결과의 `code`를 그대로 다시 보낸다(지금과 같음). 그래서 코드 모양이 달라도 harness에 분기가 생기지 않는다.
- `InstrumentId`에 시장을 넓힌다: `Market.KR_STOCK`(6자리) | `Market.US_STOCK`(거래소 + 티커). `InstrumentId.parse(code)` 하나가 두 모양을 읽고, 그 밖은 400.
- 거래·계좌 API는 거래소를 `NASD`·`NYSE`·`AMEX`로 받으므로 Broker 안에서 표 하나로 바꾼다.

### 2.2 종목 목록

- KIS 공개 마스터 `https://new.real.download.dws.co.kr/common/master/{nas,nys,ams}mst.cod.zip`(cp949, 탭 구분, 머리글 없음 — 공식 예제의 `pd.read_table` 기본값은 첫 줄을 버리는 버그가 있어 그대로 쓰지 않는다).
- 쓰는 열: `excd`(2), `symb`(4), `knam`(6), `enam`(7), `stis`(8, 2 주식·3 ETP만 넣고 지수·워런트는 뺌).
- `Instrument(code, name, market, english_name)`: 이름은 한글명, 한글명이 없으면 영문명. 영문명도 검색한다.
- 묶음 목록(`data/instruments.json`)과 하루 한 번 새로 받기(`RefreshingInstrumentCatalog`)가 국내 두 개와 미국 세 개를 함께 받는다. 지금은 국내만 받아 미국 항목을 지우므로 함께 바꾼다.

### 2.3 검색 규칙 (지금 규칙 하나를 두 목록에 그대로)

1. 코드 모양이면 코드로: 국내 6자리, 미국 티커(대소문자 무관), `NAS:NVDA` 모양.
2. 없으면 이름이 정확히 같은 것(한글명·영문명, 공백 무시·대소문자 무관).
3. 없으면 이름에 들어 있는 것.
4. 하나면 FOUND, 여럿이면 AMBIGUOUS(후보 5개), 없으면 NOT_FOUND.
5. **후보는 이름이 짧은 순**(새 규칙 하나). 미국 목록에는 종목 이름을 넣은 레버리지 ETF가 많아("디렉시온 마이크론 테크놀로지(MU) 2X" 등 마이크론만 6개), 지금 순서(목록 순)로는 5개 안에 본 종목이 빠질 수 있다. 짧은 이름이 질문에 가장 가까운 것이다.

- 지금도 "마이크론" → 국내 하나마이크론 하나만 걸려 FOUND가 된다(Explore 확인). 미국 목록이 들어오면 "마이크론 테크놀로지"와 ETF들도 걸려 AMBIGUOUS가 되고, 짧은 순으로 하나마이크론·마이크론 테크놀로지가 앞에 온다. 모델이 사용자에게 묻는다.
- "인텔"은 미국 한글명 "인텔"과 정확히 같아 FOUND(지금은 인텔리안테크로 FOUND). "아마존"은 "아마존닷컴"이 짧은 순 첫 후보.
- "엔비디아"·"애플"·"테슬라"는 미국 한글명과 정확히 같아 2단계에서 FOUND(지금은 국내 ETF만 걸려 AMBIGUOUS). 실호출 확인 목록에 넣는다.
- 티커와 국내 이름이 겹치는 경우(1단계에서 둘 다 걸림)는 AMBIGUOUS로 묻는다.
- `/instruments` 응답 후보에 `market`(KOSPI·KOSDAQ·NAS·NYS·AMS)이 붙는다(지금도 있음). harness가 후보를 보여 줄 때 시장을 함께 쓴다.

## 3. 돈과 가격 (Broker)

- `Currency`에 `USD`. `Money`·`Price`는 통화를 들고, KRW는 지금처럼 정수만, USD는 0보다 큰 소수(소수 넷째 자리까지, 마스터 `zdiv`=4).
- 호가 단위 검사는 하지 않는다(국내도 없음, KIS가 거절).
- 소수가 잘리는 곳을 고친다(Explore): `credential_api.py:505` 시세 `int(...)`, `:627` 매수 가능 `int(...)`, `aws_orders.py:105` 저장 가격 `int(...)`, `orders.py` `fingerprint()`의 `json.dumps`(Decimal 불가). 가격은 Decimal로 다루고 JSON에는 숫자로 쓴다(요청 본문은 `parse_float=Decimal`로 읽음).
- 응답에 `currency`를 붙인다: `/quote`, `/account?code=`의 `buyable`, `/history`의 `price_unit`(USD), `/account`의 미국 부분.

## 4. KIS 호출 (Broker, 미국 종목)

| 용도 | API | tr_id | 비고 |
|---|---|---|---|
| 지금 가격·전일 대비 | `overseas-price/v1/quotations/price` | `HHDFS00000300` | `last`, `diff`, `rate`, `tvol`, `tamt`, `base` |
| 시세 상세 | `.../price-detail` | `HHDFS76200200` | `tomv` 시가총액, `perx`, `pbrx`, `h52p`·`l52p`, `curr`, `e_hogau` |
| 기간 시세 | `.../dailyprice` | `HHDFS76240000` | `GUBN` 0·1·2 = 일·주·월, `MODP`=1(수정주가), `BYMD`로 과거로 이어 받기(`_dated_rows` 규칙 그대로, 날짜 `xymd`) |
| 잔고 | `overseas-stock/v1/trading/inquire-balance` | `TTTS3012R` | `OVRS_EXCG_CD=NASD`(미국 전체), `TR_CRCY_CD=USD`. 보유 종목 USD 값, `ord_psbl_qty` = 매도 가능 |
| 예수금·원화 환산 | `.../inquire-present-balance` | `CTRP6504R` | `NATN_CD=840`, `TR_MKET_CD=00`, `INQR_DVSN_CD=00`. `output2` 외화 예수금·환율, `output3` 합계 |
| 매수 가능 | `.../inquire-psamount` | `TTTS3007R` | 현재가를 `OVRS_ORD_UNPR`로 |
| 주문 | `.../trading/order` | 매수 `TTTT1002U`, 매도 `TTTT1006U` | `ORD_DVSN=00`, `OVRS_ORD_UNPR` 소수 문자열, `SLL_TYPE` 매수 "" 매도 "00", `ORD_SVR_DVSN_CD=0` |

- **quote는 두 번 부른다**(지금 가격 + 상세). 상세 API에는 달러 전일 대비가 없고, 대비를 우리가 계산하지 않기 위해서다. 주문 도구의 현재가는 첫 번째만 쓴다.
- **주문 시각**: `ORD_TMD`의 시간대가 문서에 없어 응답을 받은 시각(`received_at`)을 쓴다.
- 장 밖 주문: KIS가 오류를 준다("해외 거래소 운영시간 외 API 호출 시 애러"). 지금의 명확한 거절 규칙(`rt_cd != "0"`·`msg_cd` 있음 → REJECTED, 사유 그대로)이 그대로 적용된다.
- 투자자 동향·순위는 미국에 없다. `history` investors에 미국 종목이 오면 Broker가 400(`UNSUPPORTED_TARGET`), harness가 "투자자별 매매는 국내 종목만"으로 답한다.

### 4.1 계좌 (`/account`)

- 국내 잔고 호출(지금)에 미국 두 호출(잔고 `TTTS3012R` + 체결기준현재잔고 `CTRP6504R`)을 더한다.
- 응답: 지금 국내 필드 + `us`: `{positions: [...USD...], cash_usd, exchange_rate, total_valuation_krw, total_profit_krw}`. 정확한 필드는 실호출(§7)로 정한다.
  - 문서상 `TTTS3012R`은 USD 값만, `CTRP6504R`은 원화/외화 선택(`WCRC_FRCR_DVSN_CD`)과 예수금·환율·합계를 준다. 한 호출로 충분하면 하나만 쓴다.
- 미국 보유가 없으면 `us.positions`는 빈 목록이다.
- 해외 거래를 신청하지 않은 계좌에서 KIS가 무엇을 주는지는 실호출로 본다. 오류라면 계좌 전체를 실패시키지 않고 미국 부분만 "조회 실패(사유)"로 둘지 그때 정한다(지금 사용자 계좌로 재현되는 경우에만).

### 4.2 매수 가능 (`/account?code=NAS:NVDA`)

- `TTTS3007R`을 현재가로 부른다. KIS가 주는 두 묶음을 이름 그대로 낸다: 가진 달러로(`ord_psbl_frcr_amt`·`ord_psbl_qty`), 환전 후(`echm_af_ord_psbl_amt`·`echm_af_ord_psbl_qty`, 통합증거금·원화주문 계좌). 둘의 정확한 뜻은 실호출로 확인한다.
- 보유는 미국 잔고에서 그 종목 줄.

## 5. 주문 (Broker·harness)

- Broker `OrderRequest`: `code`(국내 6자리 | `NAS:NVDA`), `price: Decimal | None`. 미국에 `MARKET`이 오면 400(`MARKET_NOT_SUPPORTED`).
- DynamoDB 주문 기록: `price`를 Decimal로 저장·읽기. 지금은 테스트 운영이라 옛 기록 호환은 두지 않는다(사용자, 2026-10-05 원칙).
- 주문 결과 확인(체결 조회·UNKNOWN 정리)은 **국내에도 없다**(Broker README "체결 조회·취소·정정은 아직 없다"). 미국도 같게: UNKNOWN이면 "증권사 앱에서 확인" 안내(지금 문구).
- harness `order` 도구:
  - `price` 스키마를 `number`로("Limit price in the stock's currency, KRW or USD, only if the user gave one"). 국내는 정수만(지금 검사), 미국은 0보다 큰 소수.
  - 현재가를 `/quote`로 받고(지금), 응답의 `currency`로 문구를 고른다.
  - 미국에 시장가를 요청하면 주문을 준비하지 않고 "미국 주식은 지정가만 됩니다. 현재가 {p} USD 지정가로 할지 사용자에게 물으세요"를 돌려준다.
  - 확인 질문: "엔비디아(NVDA) 2주를 233.95달러 지정가로 매수할까요? (22:41 기준 현재가 233.95달러)". 달러만.
  - `int(quote["price"])`(`broker_order.py:138`)를 Decimal로.

## 6. harness 결과 문장

- `name` 설명: "A Korean or US stock or ETF: Korean name, English name or ticker". `BROKER_DESCRIPTION`의 "Overseas individual stocks are not offered: use web_search"를 "US stocks are offered; other overseas stocks: use web_search"로.
- 종목 표기: `엔비디아(NVDA, NASDAQ)`. 국내는 지금처럼 `삼성전자(005930)`. `find_instrument`가 `market`도 돌려준다.
- 금액: 통화별 도우미 하나. KRW는 지금(`_krw`), USD는 KIS 소수 그대로 `… USD`(`_exact`와 같은 방식). 시장 금액 억 원·조 원 변환(`_market_amount`)은 KRW에만.
- 미국 `quote`: 가격·전일 대비·등락률·거래량·거래대금(USD)·시가총액·PER·PBR·52주 고저. 시가총액·거래대금의 KIS 단위는 실호출로 확인해 문구에 쓴다.
- 미국 `history`: "Split-adjusted prices in USD"; 거래량은 주, 거래대금은 단위 확인 후.
- `account`: "Korea" 부분(지금)과 "US" 부분(달러 예수금, 보유 종목 USD 값, KIS 원화 환산 합계와 환율).
- 매수 가능: 미국은 "with USD on hand: …; after exchange (KIS): …".

- **실제 미국 주문은 Claude가 내지 않는다.** 확인 방법은 사용자가 정한다: (가) 한국 낮(미국 장 밖)에 PIA로 1주 매수를 요청해 KIS 거절 사유가 그대로 나오는지(체결 위험 없음), (나) 미국 장 중에 소액 1주 매수·매도.
