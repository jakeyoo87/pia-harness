# Exa Lite로 웹 검색 전환 (2026-10-24)

- 기준: pia-harness main `ed94637`, 실행 버전 0.7.19. PIA 확인 시점 main `b5fb19486`.
- 구현: Codex. 구현 검토: Claude. 사용자와 논의해 이번 작은 변경은 별도 계획 검토를 생략하고 구현 후 검토 한 번으로 진행한다.
- 브랜치: `codex/exa-lite`.

## 결정·범위

- `web_search` 이름·query 인자·ExaWebSearch 생성자·기존 Exa 키를 유지한다.
- MCP 대신 `POST https://api.exa.ai/search`에 `type=lite`, `numResults=5`, `contents.highlights=true`를 고정한다. API 키는 기존 `x-api-key` 헤더만 쓴다.
- 제목·URL·발행일·발췌를 기존 ToolLink로 바꾸고 발췌 400자·후보 최대 5개를 유지한다. 본문은 요청하거나 후보로 전달하지 않는다. 필요한 본문은 기존 web_extract가 읽는다.
- Lite는 페이지를 검색 시 다시 크롤링하지 않는 캐시 기반이다. 설명에 이 제약을 반영한다. 검색 순서(시장 소식→뉴스→웹)·본문 추출·PIA 지침은 바꾸지 않는다.
- provider `notices`는 검색 제약을 완화한 경우 등을 설명하므로 관측 문장에 함께 전달한다. `warnings`는 원문을 모델·로그에 싣지 않는다. 고정된 지원 인자만 보내고 별도 진단 체계는 만들지 않는다.
- HTTP·해석·연결 오류는 기존처럼 결과 문장으로 돌려준다. 자동 재시도, Auto fallback, 유형 선택 인자·환경변수는 추가하지 않는다.
- JSON-RPC/SSE·Title/URL 텍스트 파서와 쓰이지 않는 SSE fixture는 제거한다. MCP와 REST 두 형태를 동시에 지원하지 않는다. SDK·새 의존성·Secret·IAM은 없다.

## REST를 택한 이유

기본 MCP web_search_exa는 query·numResults만 받는다. Advanced MCP는 Lite를 받지만 본문을 기본 요청하고, JSON 응답을 다시 MCP로 감싸므로 현재 텍스트 파서도 교체해야 한다. REST는 같은 키·HTTPX로 필요한 검색 인자만 보내고 JSON을 직접 읽어 더 작다.

## 검증

- 공식 예제 형태의 가짜 JSON fixture와 MockTransport로 Lite·5개·highlights 요청, header 인증, 제목/날짜/발췌 변환, URL 없는 행, 빈 결과·잘못된 응답·HTTP/연결 오류, notices 전달을 확인한다.
- 관련 테스트 후 전체 suite, Ruff·mypy main 대비 신규 오류, format·전체 트리 공백 검사. 실제 제공기관·모델 호출이나 키 조회는 하지 않는다.
- 단위 테스트는 API 계약만 확인하며 검색 품질을 입증하지 않는다. 품질 비교는 사용자 승인 후 동일한 해외 뉴스·ETF·기업 자료 질문 약 10개로 Auto/Lite 각 1회(총 약 20검색, 기본 검색료 합 약 $0.11) 비교하는 안이다. 자동 재시도 없이 제목·관련성·날짜·공식 출처·지연을 기록한다. 아직 실행하지 않는다.
- 구현 검토 뒤 사용자 승인으로 버전·릴리스 → PIA 핀 → CI → bot-only 배포를 진행한다. 이번 구현에서 병합·버전 올림·릴리스·PIA 연동·배포는 하지 않는다.

## 구현 기록 (Codex, 2026-10-24)

- `exa_search.py`를 Lite REST 한 경로로 바꿨다. 공개 생성자·도구 이름·인자는 유지하고, 응답을 기존 ToolLink로 변환한다. 기존 MCP/SSE·텍스트 파서와 SSE fixture는 제거했다.
- 검색 결과의 `notices.message`는 후보 유무와 관계없이 모델에 전달한다. `warnings`·오류 응답 원문은 전달하지 않는다. 요청 실패는 결과 문장으로 끝내며 재시도·Auto fallback은 없다.
- 가짜 REST fixture와 MockTransport로 요청·인증·후보 제한·발췌·날짜·notices·빈 결과·잘못된 응답·HTTP/연결 오류를 검증했다. README 6.2.1을 같은 계약으로 맞췄다.
- 검증: 관련 테스트 7개·subtest 13개, 전체 257개·subtest 158개 통과. Ruff 41개·mypy 30개로 main 대비 신규 오류 0개, 변경 Python 파일 format·전체 트리 공백 검사 통과.
- 실제 Exa·모델 호출, 키 조회, 버전 변경·릴리스·병합·PIA 핀·배포는 하지 않았다. 검색 품질과 실제 계정의 과금은 이번 검증으로 확인하지 않았다.
